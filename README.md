# YnS VPN Bot

Telegram-бот на Python для демонстрации сценария заказа VPN: выбор тарифа, создание платежа через YooKassa, проверка оплаты и показ инструкции для устройства пользователя.

Проект для портфолио: показывает работу с aiogram 3, конечным автоматом состояний (FSM), callback-запросами и внешним платёжным API.

> **Статус: прототип.** После успешной оплаты бот отправляет фиксированный VLESS-ключ-заглушку. Создание VPN-пользователей, настройка сервера и выдача действующего доступа не реализованы.

## Возможности

- Команда `/start`: приветственное изображение и меню услуг.
- Выбор VPN-тарифа: 1 месяц — 100 ₽, 3 месяца — 250 ₽, 6 месяцев — 475 ₽, год — 900 ₽.
- Создание платежа в RUB через YooKassa и переход на страницу оплаты.
- Проверка статуса по кнопке «Я оплатил!»: переход к следующему шагу при `succeeded`.
- Выбор iOS, Android или Windows/PC и показ соответствующей инструкции импорта ключа.
- Возврат из выбора тарифа в главное меню.

Пункты «Собственный VPN-сервер» и «Роутер с обходом блокировок» отображаются в меню, но пока отвечают уведомлением о разработке.

## Технологии и устройство

| Компонент | Применение |
| --- | --- |
| Python, asyncio | Асинхронные обработчики и запуск приложения |
| aiogram 3 | Telegram Bot API, фильтры, inline-клавиатуры, FSM |
| YooKassa Python SDK | Создание платежа и получение его статуса |
| `asyncio.to_thread` | Выполнение синхронных вызовов платёжного SDK вне цикла событий |
| UUID | Ключ идемпотентности для каждого вызова создания платежа |
| logging | Базовое журналирование |

Сценарий FSM:

```text
/start → выбор услуги → выбор тарифа → ожидание оплаты → выбор ОС → инструкция и очистка состояния
```

В данных FSM сохраняются выбранный тариф и идентификатор платежа. Обработчики, платёжные функции и точка входа находятся в `main.py`. Бот получает обновления через long polling.

## Локальный запуск

Понадобятся Python, совместимый с установленной версией aiogram 3, токен Telegram-бота и тестовые реквизиты YooKassa. Точные версии зависимостей следует брать из `requirements.txt`; его содержимое здесь не проверено.

1. Клонируйте свой репозиторий GitHub, заменив `YOUR_GITHUB_USERNAME`:

   ```bash
   git clone https://github.com/YOUR_GITHUB_USERNAME/yns_vpn_bot.git
   cd yns_vpn_bot
   python -m venv .venv
   ```

2. Активируйте окружение.

   Windows (PowerShell):

   ```powershell
   .\.venv\Scripts\Activate.ps1
   ```

   Linux / macOS:

   ```bash
   source .venv/bin/activate
   ```

3. Установите зависимости из файла проекта:

   ```bash
   python -m pip install -r requirements.txt
   ```

4. Создайте локальный `config.py` рядом с `main.py` и заполните его своими тестовыми реквизитами:

   ```python
   API_TOKEN = "YOUR_TELEGRAM_BOT_TOKEN"
   SHOP_ID = "YOUR_YOOKASSA_SHOP_ID"
   SECRET_KEY = "YOUR_YOOKASSA_TEST_SECRET_KEY"
   ```

   Именно эти три имени импортирует `main.py`. Загрузка `.env` в нём не реализована; поддержка dotenv не подтверждена, поскольку содержимое исходного `config.py` не проверено.

5. Поместите изображение `приветственная.png` в корень проекта: обработчик `/start` открывает его по относительному пути.

6. В `create_yookassa_payment` проверьте `return_url`: ссылка должна вести на вашего Telegram-бота. Запускайте приложение из корня проекта:

   ```bash
   python main.py
   ```

## Проверка демонстрационного сценария

Используйте тестовый магазин YooKassa и тестовые реквизиты.

1. Отправьте `/start`, выберите VPN и тариф.
2. Откройте страницу оплаты и выполните тестовый платёж.
3. Нажмите «Я оплатил!». При статусе `succeeded` бот предложит выбрать ОС.
4. Выберите устройство: бот отправит инструкцию и ключ-заглушку, затем очистит состояние.

Этот сценарий проверяет интерфейс и платёжный переход. Он не подтверждает возможность VPN-подключения. Инструкции по клиентским приложениям — статические тексты из кода.

## Ограничения и дальнейшее развитие

- Нет интеграции с VPN-сервером, генерации действующих ключей, учёта срока доступа и отключения подписок.
- Нет базы данных и постоянного хранилища FSM; состояние заказа теряется при перезапуске.
- Оплата проверяется вручную кнопкой; webhook-обработчик отсутствует.
- Для каждого создания платежа генерируется новый UUID: защита от повторного создания одного заказа между запросами не реализована.
- Нет отдельной обработки сетевых ошибок платёжного API и сценариев восстановления заказа.

Следующие шаги: постоянное хранение заказов, обработка ошибок и повторных действий, автоматическое подтверждение оплаты, интеграция с VPN-сервером и тесты ключевых сценариев.

## Конфигурация и публикация

Не публикуйте рабочие токены, платёжные ключи и пользовательские данные. Для публичного примера конфигурации используйте только заглушки, как в примере выше.

Добавьте в `.gitignore`:

```gitignore
config.py
.env
*.env
.venv/
venv/
__pycache__/
*.pyc
```

Перед публикацией на GitHub проверьте состав файлов и историю коммитов. `.gitignore` не удаляет уже отслеживаемые секреты. Если секрет был опубликован, его необходимо перевыпустить.
